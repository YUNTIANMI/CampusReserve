# Phase 4：资源详情与时间选择

- [x] 图片展示
- [x] 资源信息
- [x] 日期选择
- [x] `TimeSlot`
- [x] 可用/不可用状态
- [x] 获取指定日期可用时间
- [x] 选择时间
- [x] 预约按钮状态

验收：
可查看指定资源在指定日期的时间段。

验收结论（2026-09-15 实测）：
- 端到端测试 81/81 通过（`tools/e2e/e2e-phase4.js`），Phase 1 / Phase 2 / Phase 3 回归 36/36、47/47、65/65
- 资源信息区与时间段区**各自独立四态**：切换日期失败只影响时间段区，资源名称/地点/描述不会一并消失
- 日期条（未来 7 天）为静态内容，不随任何四态变化；某个日期取不到时段时仍可切换其他日期
- 时间段状态 `AVAILABLE` / `BOOKED` / `DISABLED` 三态均可见；今天的时段按当前时间判定为「不可预约」
- 只有 `AVAILABLE` 可被选择；已选时段再次点击即取消选择；切换日期会清空已选时段
- 预约按钮状态：未选时段时禁用且点击无任何反馈，选中后文案为「预约 HH:mm-HH:mm」并可点击
- 资源不存在（接口正常返回但查无此资源）落到 empty 态而非 error 态，只给「返回上一页」
- 非法 `id`（非数字、`0`、非正整数）一律判定为参数错误并展示错误态
- 图片展示：`imageUrl` 存在时渲染 `<image>`，缺省时渲染资源类型占位块（开发期数据源不提供图片，
  见 `docs/PROJECT_MEMORY.md` §11 开发期数据源说明）

阶段边界（刻意留在后续阶段）：
- 预约按钮的**提交动作**属于 Phase 6（校验 + `POST /api/bookings`），本阶段点击只给出提示

# Phase 5：用户登录

- [x] 登录入口
- [x] 微信登录流程
- [x] 登录状态保存
- [x] 用户信息展示
- [x] 登录失败处理
- [x] 未登录状态处理

验收：
未登录用户进入预约流程时能正确引导登录。

验收结论（2026-09-15 实测）：
- 端到端测试 63/63 通过（`tools/e2e/e2e-phase5.js`），Phase 1 / Phase 2 / Phase 3 / Phase 4 回归
  36/36、47/47、65/65、81/81
- 登录入口两处：首页顶部用户区（点击进登录页）、我的预约页未登录引导的「去登录」按钮
- 一键登录流程：`wx.login()` 取一次性 code → `POST /api/auth/login` 换登录态（Phase 10 接真实后端，
  本阶段由 `services/mock-auth.ts` 顶替），点击后按钮进入「登录中…」，成功后自动返回来源页
- 登录态真源是 `store/auth.ts` 的模块级内存态，同时写入本地缓存（`CR_AUTH_TOKEN` / `CR_USER_INFO`）
  并镜像到 `app.globalData`；页面只读副本、在 `onShow` 同步
- 冷启动恢复：凭证与用户信息**同时有效**才算已登录；两者不匹配（如只有凭证）时回到未登录并清掉残留
- 用户信息展示：登录页展示昵称与用户 ID，头像用昵称首字占位（开发期数据源不提供头像）
- 登录失败：停在登录页并展示错误提示，按钮文案恢复为「微信一键登录」可直接重试
- 未登录处理：我的预约页展示登录引导而非空白，详情页点预约先弹「需要登录」引导、确认后进登录页，
  登录返回后**详情页已选时段仍在**（`navigateBack` 复用原页面实例）
- 退出登录：登录页二次确认后清空内存态与缓存，各页面在 `onShow` 回到未登录展示

阶段边界（刻意留在后续阶段）：
- `POST /api/auth/login` 的真实后端实现属于 Phase 10，本阶段由开发期数据源顶替
- 退出登录只清本地登录态，通知服务端失效属于 Phase 10

# AI 协同开发流程

每个 Phase：

```text
Phase
 ↓
拆 Task
 ↓
Codex 读取项目状态
 ↓
分析任务
 ↓
提出计划
 ↓
开发
 ↓
测试
 ↓
开发者验收
 ↓
更新 PROJECT_MEMORY.md
 ↓
Git Commit
```

禁止跨阶段一次性实现大量功能。
